# RAG: база знаний ИИ-наставника

ИИ-наставник отвечает не только из общих знаний модели, но и с опорой на базу StepByStep:
реальный опыт поступивших, гайды команды и проверенные факты. Каждое утверждение из базы
модель помечает ссылкой на источник `[1]`, `[2]`, а в чате под ответом показывается, откуда он.

## Схема

```
ЗАГРУЗКА                                             ОТВЕТ НА ВОПРОС
────────                                             ───────────────
/admin «Добавить» ──┐                                вопрос ученика + его профиль
/share (выпускники) ┼─► документ ─► модерация        │
seed (стартовые)  ──┘      │       (pending →        ├─► поиск по гайдам и фактам (по вопросу)
                           │        approved)        └─► поиск по опыту (вопрос + профиль)
                           ▼                                     │
                 нарезка на куски (chunk.ts)            гибридный поиск (search.ts):
                 + шапка с метаданными                  векторы (смысл) + BM25 (слова),
                           │                            слияние RRF, ≤2 куска на документ
                           ▼                                     │
                 эмбеддинги (embeddings.ts)                      ▼
                 multilingual-e5-small, локально        <knowledge> в системном промпте
                           │                            (retrieve.ts) → Claude → ответ
                           ▼                            + источники первой строкой потока
                 .data/knowledge.json (store.ts)
```

## Файлы

| Файл | Что делает |
|---|---|
| `src/lib/rag/types.ts` | Модель данных: документ, чанк, метаданные (вуз, год, результат, профиль автора) |
| `src/lib/rag/chunk.ts` | Нарезка по абзацам (~900 символов, перекрытие 150) + шапка с метаданными в каждом чанке |
| `src/lib/rag/embeddings.ts` | Эмбеддинги. Точка замены модели |
| `src/lib/rag/store.ts` | Хранилище (JSON-файл). Точка замены на Postgres + pgvector |
| `src/lib/rag/search.ts` | Гибридный поиск, пороги релевантности |
| `src/lib/rag/retrieve.ts` | Что именно получает наставник: два поиска + форматирование для промпта |
| `src/app/api/mentor/route.ts` | Наставник: системный промпт (честность, reach/target/safety, ссылки) + RAG |
| `src/app/api/knowledge/*` | API админки: список, добавление, модерация, поиск, seed, reindex, eval |
| `src/app/api/experience/route.ts` | Приём отзывов из публичной анкеты (статус pending) |
| `src/app/admin/page.tsx` | Админка базы знаний |
| `src/app/share/page.tsx` | Публичная анкета для поступивших |
| `src/data/knowledge-seed.ts` | Стартовые гайды, 3 ДЕМО-истории и контрольный набор вопросов `EVAL_SET` |

## Как пользоваться

1. `npm run dev`, открыть http://localhost:3000/admin.
2. «Обзор» → «Загрузить стартовые гайды и демо-истории». При первом запуске модель эмбеддингов
   (~120 МБ) скачивается в `.cache/models`.
3. «Проверка поиска» — посмотреть, что получит ИИ на конкретный вопрос.
4. «Тест качества» — hit rate и MRR по `EVAL_SET`. Прогонять после каждого изменения.
5. Отзывы из `/share` появляются во вкладке «Модерация» и попадают к ИИ только после одобрения.

Для продакшена задать в `.env.local`:
- `ANTHROPIC_API_KEY` — ключ Claude API для наставника;
- `ADMIN_TOKEN` — пароль админки (без него `/admin` открыт только в режиме разработки).

## Ключевые решения

- **RAG, а не дообучение.** Знания меняются каждый год; база обновляется мгновенно, а модель
  не выдумывает устаревшие дедлайны. Fine-tuning имеет смысл позже и только для стиля.
- **Опыт ищется с учётом профиля ученика.** Запрос = вопрос + цели, экзамены, школа. Так находятся
  истории людей с похожим профилем, включая отказы.
- **Шапка с метаданными в каждом чанке.** Запрос «отказ из Йеля с SAT 1450» находит отзыв, даже если
  в самом абзаце нет ни вуза, ни баллов.
- **Гибридный поиск.** Векторы ловят перефразировки, BM25 — точные названия и цифры (SAT 1450, KAIST).
- **Модерация.** Ничего из публичной анкеты не попадает к ИИ без проверки человеком.
  Контакт автора хранится только для команды и не передаётся в промпт.
- **Честность в промпте.** Наставник не обнадёживает без оснований, делит вузы на reach, target и safety,
  помечает демо-записи и ответы из общих знаний.

## Что делать дальше (задачи для ML-инженера)

1. **Хранилище → Postgres + pgvector** (например, Supabase). Переписать функции `store.ts`
   на SQL, поиск по векторам — через индекс HNSW. Остальной код не меняется.
2. **Эмбеддинги.** Сравнить на `EVAL_SET` текущую `multilingual-e5-small` с `multilingual-e5-large`,
   OpenAI `text-embedding-3-large`, Voyage `voyage-3`. После смены модели — «Переиндексировать всё».
3. **Реранкер.** Добавить второй этап: топ-20 из гибридного поиска → cross-encoder / Cohere Rerank /
   Voyage rerank → топ-5. Обычно заметно повышает точность.
4. **Контрольный набор.** Расширить `EVAL_SET` до 100–200 реальных вопросов учеников
   (с ожидаемыми документами) и добавить оценку самих ответов (LLM-as-judge: опирается ли ответ
   на источники, нет ли завышенного оптимизма).
5. **Слой «факты».** Автоматическая проверка дедлайнов и требований по официальным сайтам
   по расписанию + поле `verifiedAt`; устаревшие факты — на повторную проверку.
6. **Поиск в интернете в момент вопроса** для свежих данных (web search tool модели),
   с явной пометкой в ответе, что это не из базы StepByStep.
7. **Обезличивание.** Автоматически убирать имена и контакты из текстов отзывов перед индексацией.
8. **Удалить ДЕМО-истории**, когда появятся настоящие отзывы.

## Данные: откуда брать

- Анкета `/share` — главный источник. Распространять через Telegram-канал.
- Интервью с поступившими (текст → «Добавить» в админке).
- Официальные сайты вузов и программ — для слоя «факты».
- Reddit и другие форумы — **только по правилам площадки**: у Reddit коммерческое использование
  и обучение ИИ требуют отдельного соглашения. Без него — только ссылки, без копирования текста в базу.
